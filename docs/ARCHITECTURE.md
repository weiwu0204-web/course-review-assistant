# 架构设计

## 核心判断：提取分三层，越靠前越便宜

这是整个项目最重要的一个设计决定。

```
第 1 层  纯解析        零成本        文本、表格、备注页、OMML 公式、图表数据
第 2 层  嵌入图片      视觉模型      截图、示意图、以图片形式存在的公式
第 3 层  整页渲染      最贵（未实现）  扫描版幻灯片
```

### 为什么必须分

直觉上「图片就丢给多模态模型」很省事，但实测下来这是错的。

**图表不是图片，数据在 XML 里。** `chart.plots[].categories` 和
`plot.series[].values` 直接就能读出来，准确且免费。
让视觉模型去「看」一个柱状图，它返回的是一堆近似值——花了钱，还更不准。

**PowerPoint 2007 以后的公式是 OMML，不是图片。** 它是一段 XML，
python-pptx 不暴露这一层，但直接读 `shape._element` 里的 `oMath` 节点就能拿到。

**备注页是整个提取器里投入产出比最高的一处。** 老师常把真正的考点写在这里
（「这题必考」「去年考过」），而它只是纯文本，一行代码就能读。

实测数据：同一份样例 PPT，图表页提取字符数从 **7 → 113**，
备注从 **0 → 80 字**，都是零成本拿到的。

## 图片的三层过滤

第 2 层真正棘手的地方不是「怎么发给模型」，而是**哪些图值得发**。

雾围的真实课件（19 页）提取出 42 张图，看一眼才知道里面有多少水分：

| 过滤层 | 规则 | 原理 |
|--------|------|------|
| 面积 | < 150×150 像素丢弃 | 图标、logo、背景纹理 |
| 纯色 | 灰阶标准差 < 30 丢弃 | 白底占位框、纯色遮罩 |
| 重复 | 同一张图出现 ≥3 页丢弃 | 母版背景、水印 |

**42 → 6 张，token 从 16128 降到 2304，降了 86%。**

### 两个实现细节

**用标准差，不用极值差。** 一开始用 `getextrema()` 判断纯色，
结果白底矩形带一圈细边框就能骗过检查——极值差很大，但信息量是零。
换成 `ImageStat.Stat(im.convert("L")).stddev[0]` 后就准了：
空白图集中在 11~19，有内容的在 40 以上，中间有很干净的间隔。

**注意 Pillow 版本。** `Image.stat()` 这个快捷方法在 Pillow 12.3 上不存在，
必须用 `ImageStat.Stat(im)` 显式调用。踩过一次。

## 模型选择

文本和视觉**共用同一个 base_url 和 API Key，只换 model 字符串**：

```
AI_MODEL         = deepseek-v4-flash              纯文本
AI_VISION_MODEL  = deepseek-v4-flash-vision-exp   带图片时
```

`collect_images()` 决定这次请求有没有图要发，有图就用视觉模型，没图就退回纯文本。
所以「用不用多模态」不是一个需要用户操心的开关——它是自动的。

> ⚠️ `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 永久停用。
> 另外别顺手迁到 `deepseek-v4-pro`，那是 Flash 的 3.1 倍价格，不是迁移目标。

## 数据流

```
上传课件（.pptx / .pdf）
  └─ uploads/<uuid>/原文件名
       └─ extract_any()  按后缀分发，产出同一个 ExtractionResult
            ├─ .pptx → extract_pptx
            │    ├─ 第 1 层：文本 / 备注 / 公式 / 图表 → format_for_ai()
            │    └─ 第 2 层：嵌入图片 → 三层过滤 → PNG
            └─ .pdf  → extract_pdf
                 ├─ 逐页文本（提取后做文字层健康检测，乱码即报错）
                 └─ 不做图片提取（属于后续 OCR 路线）
                                        ↓
                              collect_images()
                                        ↓
                       有图？─── 是 ──→ 视觉模型
                        │
                        └────── 否 ──→ 纯文本模型
```

每次上传单独一个 uuid 目录，避免同名文件互相覆盖。

两种格式产出**同一个 `ExtractionResult`**，所以提示词组装、AI 生成、批量总册、
成本估算全都不感知格式——新增格式只需在 `extractor.py` 加一条分支。
PDF 侧为什么必须做「文字层健康检测」，见 [PDF-SUPPORT.md](./PDF-SUPPORT.md)。
