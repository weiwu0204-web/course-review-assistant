# 产品需求文档（PRD）：PPT 复习助手

## 1. 背景与核心问题

不同高校的同名专业课在教学范围、章节取舍和期末考法上差异很大。学生在复习阶段面临三个具体痛点：
1. **翻阅成本高**：一门课通常有 10–20 份课件、数百页幻灯片，重点常散落在备注页、图表 XML 和公式中。
2. **通用 AI 长程静默遗漏**：把整门课材料一次性丢给通用大模型或通用 Agent 时，输出在后半程会出现肉眼难以察觉的大幅缩水（实测 14 节课程前半程术语覆盖率 95.1%，后半程跌至 83.9%）。
3. **缺乏可核对依据**：普通问答给出的结论没有精确到课件页码的来源，或者标了页码但内容与原文对不上，学生仍需人工翻回原课件逐一核实。

## 2. 目标用户与双运行形态

| 形态 | 目标场景 | 入口与存储边界 |
|---|---|---|
| **服务版（主形态）** | 多学生/多账号通过浏览器管理各自课程、持续更新课件版本、生成总册与反复追问 | `app.service_main:create_app` + `app.worker`；MySQL 存账号/归属/版本/状态，私有对象桶存原件与成品 |
| **桌面版（兼容基线）** | 单人本机零运维即开即用（支持 pywebview 桌面壳） | `app.main:app`；本地文件系统与 `%APPDATA%` 自持 API Key |

## 3. 核心用户场景

1. **版本化课程材料管理（001）**：用户上传或更新 `.pptx/.pdf` 课件与往年试题；更新生成递增版本号，已提交的批任务和已建立的知识库固定使用创建时的版本快照，互不污染。
2. **整课批量生成与覆盖率补漏（001 / 002）**：按序逐节提取（本地零成本解析优先，嵌入图按需走视觉模型）并汇编总册；单节失败可独立重试；支持本地零成本计算术语覆盖率，并在配置真实模型单价后按成本上限执行 MCP 自动补漏。
3. **按页溯源的知识库问答（002）**：基于选定课件版本建立私有知识库，通过 SSE 流式返回检索页码、答案与术语级引用核验状态（「引用可信 / 引用待核」），未命中课件内容时明确拒答而不编造。
4. **个人历史与可观测统计（002）**：查看近期批任务各节覆盖率诊断、补漏记录及知识库问答次数，跨账号完全隔离（他人访问统一返回 404）。

## 4. 明确非目标（Non-goals）

- **不做全网自动搜题**：公开网络题库无法反映具体高校出题风格，题目来源限定为用户上传的本校往年卷或显式标注的模拟预测题。
- **不把损坏/扫描版 PDF 乱码喂给模型**：字体映射表损坏或纯扫描 PDF 在提取体检阶段直接拦截并明确提示，在 OCR/整页渲染方案落地前不静默产出残缺文档。
- **不在未配置计价时启用自动补漏**：避免无单价约束下的未知模型调用开销；默认预览环境使用 `demo` 模式零付费运行。
- **当前阶段不包含公网自助注册、计费充值与多人协作共享课程**。

## 5. 成功指标与当前基线

| 维度 | 指标定义 | 当前状态与实测值 | 出处 |
|---|---|---|---|
| **整课覆盖率** | 「复习指南/详细」档逐节术语覆盖率均值及前后半程衰减 | **97.7%**（前 98.6% / 后 96.9%，衰减 1.7pp） | [eval/README.md](../eval/README.md) |
| **自动补漏收敛** | 低覆盖章节（58%–89%）在 ≤40% 生成成本上限内的修复后覆盖率与误触发率 | 三组样本均修至 **100%**（成本占 26%–37%），存量 27 节 **0 误触发** | [P2 验收归档](archive/desktop/P2-ACCEPTANCE.md) |
| **检索与引用核验** | 单课按页检索延迟；真实流式问答中可信引用占比与页码编造数 | 检索 **p50 0.20 ms**；引用可信 **89.8%**（114/127），编造页码 **0 条** | [P3 设计与实验归档](archive/desktop/P3-RAG.md) |
