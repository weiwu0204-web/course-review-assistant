# PDF 课件支持

> 状态：已实现（0.8.0，2026-09-10）｜代码：`app/services/pdf_extractor.py` + `extractor.py`

## 一句话

支持 PDF 课件不是「多解析一种格式」那么简单——**「文字版 PDF」不等于「能提取出文字」**。
本项目先提取、再体检：不健康的直接拦下并提示走 OCR，**绝不把乱码喂给模型**。

## 架构：加一层分发，下游零改动

`extract_any(path, image_dir) -> ExtractionResult` 按后缀分发：

| 后缀 | 提取器 | 依赖 |
|---|---|---|
| `.pptx` | `extract_pptx` | python-pptx |
| `.pdf` | `extract_pdf` | pypdf（原就在依赖中，用于试题解析） |

两个提取器产出**同一个 `ExtractionResult`**，所以提示词组装、AI 生成、批量总册、
成本估算**全部无需改动**。新增格式只需在 `extractor.py` 里加一条分支——
`SUPPORTED_EXTENSIONS` 是格式的唯一真相来源（后端校验与前端 `accept` 都指向它）。

## 核心：文字层健康检测

### 为什么需要

某些生成方式（**打印成 PDF** / pdftopdf 过滤器）会把字体的 ToUnicode 映射表写坏：
字形轮廓还在、阅读器能正常显示、**肉眼完全看不出问题**，但字符无法还原成 Unicode。

实测某课件的 SimSun 字体，整张 ToUnicode 表只剩一条映射：

```
1 beginbfrange
<0100><0101><201c>     ← 只映射了左右双引号
endbfrange
```

其余中文字符全部丢失。**换任何解析库都救不了——映射表本身不存在。**

### 实测数据（6 份真实 PDF，乱码 = U+0080–U+02FF 字符占比）

| 文件 | 页数 | 乱码占比 | 结果 |
|---|---|---|---|
| 4.2_2 磁盘调度算法 | 4 | 42.1% | 损坏 |
| 4.2_4 磁盘的管理 | 2 | 36.3% | 损坏 |
| 4.2_3 减少磁盘延迟时间的方法 | 3 | 18.1% | 损坏 |
| 5.1_1 I/O 设备的基本概念和分类 | 2 | 17.9% | 损坏 |
| LLM（英文课件，130 页） | 130 | **0.0%** | 健康 |
| 个人简历（中文） | 1 | **0.0%** | 健康 |

损坏与健康**完全没有重叠**，阈值取 5% 足够安全。

### 判据为什么不是「中文占比」

因为英文课件本来就没有中文。实测 `LLM.pdf` 中文仅占 0.6%，但内容完全正常
（`Selected Topics on Large Language Models`）——按中文占比判会**误杀正常文件**。
**乱码字符占比**才是可靠信号。

### 检测失败时的行为

抛 `PdfExtractionError`（继承 `PptExtractionError`，上层统一捕获），API 返回 400：

> 文字层已损坏（中文字符无法还原成可读文本）。这类 PDF 多是「打印 / 导出」生成的，
> 字形能显示但无法被程序读取，需要走 OCR 识别。可以先自己验证：在阅读器里试着
> 复制一段中文，若粘贴出来是乱码或复制不出来，即可确认。

**为什么宁可报错也不放行**：乱码喂给模型会生成一份"看起来完整、内容全是噪声"的
复习文档——比直接失败更糟，用户可能直接把噪声当复习资料背。

## 附带：跨页重复行过滤

PDF 没有 PPT 的「形状」概念，水印会实打实混进文本（实测某课件水印每页重复 3 次，
130 页的课件光水印就占数千 token）。按「短行出现在 ≥60% 页面」判定并剔除；
**少于 3 页不过滤**，避免把真实标题当噪声删掉。

## 已知边界

| 边界 | 说明 |
|---|---|
| 没有备注页 | PPT 的备注是老师写考点的地方（项目里投产比最高的信息源），PDF 无此概念，`notes` 恒为空 |
| 不做图片提取 | PDF 图片需整页渲染，属 OCR 路线；当前 `image_count = 0` |
| 阅读顺序 | pypdf 按内容流顺序输出，多栏 / 图文混排的 PDF 可能顺序错乱 |
| 扫描版 PDF | 无文字层，提取为空同样被拦下 → 提示走 OCR |

## 后续：扫描版与损坏文字层怎么救

两条路都归入 CV 路线（见 [CV-INTEGRATION.md](./CV-INTEGRATION.md)）：

1. **整页渲染 + OCR**：PDF 自带渲染器（pypdfium2 / PyMuPDF 可直接渲染成图），
   不需要 PowerPoint / LibreOffice——这一点比 PPT 的「整页渲染」更容易落地。
2. **视觉模型兜底**：渲染出的整页图交给多模态模型，作为 OCR 失败时的回退。

优先级：先把健康的文字版 PDF 走通（**已完成**），扫描版与 OCR 合并到 P1 一起做。
