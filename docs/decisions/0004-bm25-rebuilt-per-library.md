# 0004：知识库采用纯 Python 按页 BM25 并在读取时从分块重建

- **状态**：已采用
- **日期**：2026-11-26（源自 [P3 设计与实测](../archive/desktop/P3-RAG.md) 及 [002 技术方案](../specs/002-service-study/design.md)）

## 背景与约束
课程知识库要求每条回答都能精确追溯到源课件页码并做自动引用核验，同时在服务版多 API 实例部署下不能依赖单进程内存里的可变全局状态。此外，项目接入的四家主流对话模型配置中并不统一提供 Embedding 接口。

## 决策
1. **分块与检索算法**：以**幻灯片/PDF 单页**为最小分块单位（保留精确页码元数据），使用自研零依赖纯 Python **BM25 + 三层分词（英文术语 / 数值单位 / 中文 2-gram）+ 可选 LLM 查询改写**，不引入向量数据库或 `jieba` 分词词典。
2. **服务版持久化与无状态加载**：建库时固定当时选定课件的版本清单，提取分块 JSON 存入私有对象存储，归属与元数据存入 MySQL；每次问答打开知识库时从分块对象即时重建内存 BM25 索引，不在多进程间共享可变索引缓存。

## 备选方案与取舍

| 候选方案 | 优势 | 放弃原因 |
|---|---|---|
| **按页 BM25 + 按需重建（选定）** | 14 份课件（325 页）实测建索引仅 **11 ms**、暴力打分 **p50 0.20 ms**、术语召回 **98.8%**；零外部依赖、可离线测试、多 API 实例天然无状态一致 | 口语化跨页提问受限于词面邻近页竞争（精确锚点页命中 65%，同文件命中 90%） |
| 神经 Embedding + 向量库（FAISS / pgvector） | 语义泛化能力强 | 在百页级单课规模下耗时与外部 API 依赖显著增加，而口语短板已通过一次轻量查询改写补齐 |
| 固定字数滑窗切分（如 512 tokens） | 分块长度均匀 | 单块跨多页会破坏“引用精确到具体第 N 页”的核心产品承诺 |

## 后果与演进触发条件
- **正面收益**：无需额外部署向量引擎，任何 API 实例均可独立处理任意授权知识库请求，检索得分完全确定可解释。
- **代价与残余风险**：建库目前受总输入大小（100MB）与分块 JSON 上限（16MB）保护；当单库规模显著增大或同课相邻页漏召回影响体验时，再引入异步建库任务与相邻页窗口重排。
