# 0005：知识库问答使用 SSE 单向事件流传输来源、正文与引用核验

- **状态**：已采用
- **日期**：2026-11-26（源自 [002 技术方案](../specs/002-service-study/design.md) 与 [P3 设计](../archive/desktop/P3-RAG.md)）

## 背景与约束
知识库问答需要依次返回「命中的课件页码来源 → 逐字生成的回答 → 生成结束后的术语级引用核验结果」，若等待整段生成与核验全部完成后再一次性返回，用户在数秒内只能面对空白页面。

## 决策
使用基于标准 HTTP 的 **SSE（Server-Sent Events，`text/event-stream`）** 承载问答流：
1. 先校验知识库 `owner` 归属并完成检索，推送 `sources` 事件（含命中页与检索耗时）。
2. 流式推送 `delta` 增量文本事件；未命中任何相关课件片段时直接返回可解释说明，不调用模型凭空编造。
3. 生成完毕后在服务端运行确定性引用核验（复用术语比对判据），推送核验汇总与 `done` 事件并写入个人问答历史。
4. 若流式传输已经开始后上游发生异常，统一发送脱敏的通用 `error` 事件，不暴露底层模型供应商报错细节。

## 备选方案与取舍

| 候选方案 | 优势 | 放弃原因 |
|---|---|---|
| **HTTP SSE（选定）** | 契合“单次提问 → 持续下行流”的单向模型；标准 HTTP 认证头、代理穿透与 FastAPI `StreamingResponse` 原生支持，无需额外连接状态管理 | 不支持同一连接上的客户端双向插话（本场景不需要） |
| WebSocket | 全双工通信 | 需要额外处理长连接鉴权、心跳保活与多实例状态，对单轮问答属于过度设计 |
| 普通同步 JSON 响应 | 实现最简单 | 首屏等待时间长（含改写与全文生成），交互体验差 |

## 后果与演进触发条件
- **正面收益**：前后端协议轻量清晰，易于在测试中直接消费生成器事件流断言（无需启动真实 WebSocket 服务器）。
- **代价与残余风险**：启用查询改写时，首个 `delta` 前仍有一跳非流式改写耗时（实测中位约 1.2–1.9s）；后续可通过提前推送阶段状态事件进一步优化首反馈感知。
