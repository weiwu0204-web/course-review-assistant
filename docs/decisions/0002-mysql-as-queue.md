# 0002：首版使用 MySQL 短事务与租约充当作业队列

- **状态**：已采用
- **日期**：2026-11-26（源自 [001 服务基础设计](../specs/001-courseware-revision/design.md)）

## 背景与约束
服务版批量生成整门课手册耗时较长，必须将任务执行移出 API 进程交由独立 worker 异步处理，同时需要支持 worker 崩溃后的自动接管、单节失败重试以及防止过期 worker 覆盖新结果。在私有预览阶段，系统已经依赖 MySQL 持久化课程与任务状态。

## 决策
不额外引入外部消息队列中间件；直接基于 MySQL `jobs` 表实现任务队列：
1. Worker 在**短事务**内将到期或待处理的 `queued/running` 行更新为 `running`，写入唯一领取标记（`claim_token`）并按数据库时钟计算租约到期时间（`lease_until`）。
2. 课件下载、本地提取、模型生成与结果上传全部在**数据库事务之外**执行。
3. 续租与最终状态提交必须携带匹配的 `claim_token`；租约过期被新 worker 接管后，旧 worker 的滞后提交因标记不匹配而被原子拒绝。

## 备选方案与取舍

| 候选方案 | 优势 | 放弃原因 |
|---|---|---|
| **MySQL 租约队列（选定）** | 零额外运维组件，任务状态与业务元数据天然强一致，崩溃恢复与幂等逻辑清晰可测 | 高频轮询在极高并发 worker 数下会产生行锁竞争 |
| Redis / RabbitMQ 独立队列 | 吞吐高、支持阻塞推送唤醒 | 私有预览并发量远未触及数据库瓶颈；额外引入中间件会增加双写一致性故障面与部署复杂度 |

## 后果与演进触发条件
- **正面收益**：部署拓扑精简（仅 MySQL + 对象存储），已在隔离 MySQL 8.0.45 上通过双 worker 并发争抢与进程强杀恢复验证。
- **代价与残余风险**：租约过期接管会导致该单节被再次生成，可能产生一次额外的模型调用成本（但仅有效领取者的产物会被发布）。
- **何时重新评估**：当多 worker 轮询导致数据库锁等待明显上升，或建库/评测等异构长任务规模显著扩大时，再评估独立队列中间件。
