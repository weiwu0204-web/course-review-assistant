# 复盘记录：001 / 002 服务版重构过程与改进

> 日期：2026-11-28 ｜ 范围：服务版基础（001）与学习工作台（002）两轮迭代

## 1. 做成了什么

- 在不改动桌面版使用方式的前提下，把单机工具拆出了独立的多人服务版（API + Worker + MySQL + 私有对象存储）。
- 001 验证了多账号隔离、课件版本固定、双进程抢任务和 Worker 崩溃后的租约接管（314 项测试通过）。
- 002 补齐了按版本建知识库、SSE 流式引用问答，以及保留数据卷做升级和回滚演练（318 项测试通过，本机切回旧版约 7.8 秒恢复就绪，详见 [验收记录](../runbooks/service-verification.md)）。

## 2. 哪里没做好

1. **单次提交太大，没法认真审**：001 和 002 的实现提交都在 1500 行以上，拆分静态资源那笔改了五千行，人眼很难逐行看清。
2. **002 的规格和代码混在同一个提交里**：虽然写了规格文档，但和代码一起提交，事后看不出是不是“先写规格再写代码”；测试和实现也总是一起交，没有留下先红后绿的证据。
3. **没有留下审查记录**：做完测试就提交了，没有单独记下核对了哪些权限边界和删除的代码。
4. **CI 写了但没真跑起来**：当时一直没推送到 GitHub，云端检查和主干分支保护都没启用。
5. **公开仓库里混进了课程衍生文件**：早期把真实课件生成的复习文档和评测题放进了版本库，不适合公开展示。

## 3. 改了什么（把教训变成硬规则）

| 暴露的问题 | 现在的防再犯措施 |
|---|---|
| 单次提交过大 | 在 [Git 规范](../workflow/git-workflow.md) 规定单个 PR 净改动 ≤ 400 行，文件移动与逻辑修改分开提交 |
| 规格与代码混交、缺 TDD 证据 | 在 [开发流程](../workflow/development-process.md)、[ppt-spec](../../.agents/skills/ppt-spec/SKILL.md) 和 [ppt-tdd](../../.agents/skills/ppt-tdd/SKILL.md) 要求规格单独提交、关键验收项先交失败测试再交实现 |
| 缺少人工审查留痕 | 新增 [ppt-review](../../.agents/skills/ppt-review/SKILL.md) 与 [审查记录模板](../templates/review.md)，强制检查权限派生、短事务和被删除代码 |
| 云端门禁形同虚设 | 启用 GitHub `main` 分支保护，并在 [CI 工作流](../../.github/workflows/service-checks.yml) 接入 `ruff`、模块依赖测试、文档死链检查和回归测试 |
| 仓库混入第三方语料 | 从历史中彻底清理 9 个衍生文件，更新 [.gitignore](../../.gitignore) 并补充 [评测复现说明](../../eval/README.md) |
