# P4 · 可观测（埋点与统计页）

> 状态：**埋点 + 统计页 + 横评脚本已交付（2026-10-19）**；横评本身**未跑**（需要 4 家 key，且建议先修检索）。

## 1. 为什么先做这一半

P4 原本包含两块：**埋点统计页** 与 **多模型横评**。两者的依赖关系是单向的：

> 横评要回答的是"哪家模型在**这个任务**上性价比最高"，而这个"任务"包含检索。
> 如果检索层还有 35% 的题材料进不来（P3 §21.2 实测：锚点页 top-5 命中 13/20），
> 四家模型会一起卡在同一处，横评结论退化成"都答不出"——**花了钱，测的是检索不是模型**。

所以顺序是：**先埋点（本次）→ 修检索 → 再横评**。
而且埋点零成本、产物直接能写进简历，比横评更早变成可讲的数字。

## 2. 埋了什么

### 2.1 生成侧（`output/<batch_id>/batch.json` → `jobs[]`）

| 字段 | 含义 | 为什么要它 |
|---|---|---|
| `prompt_tokens` / `completion_tokens` | 该份实际消耗 | 只有成本算不出"输入长还是输出长"；跨模型对比必须同口径 |
| `duration_s` | 单份耗时（`perf_counter` 计时） | 用 `started_at`/`finished_at` 相减会被系统时间跳变污染 |
| `model` | 实际出稿的模型 | 同一门课换模型后，不记就分不清哪份是谁生成的 |

**旧记录没有这些字段** → 加载后是 0。统计时把 0 当作「未记录」并**排除在均值之外**，
同时把「有记录的份数」一并报出来（`tokens.covered_jobs`）。把 0 算进均值会把 token 平均拉低。

⚠️ **口径缺口（如实记录）**：`prompt_tokens`/`completion_tokens` 只统计**主生成**那一次调用；
P2 补漏（repair）的 token **没有**并入（它的钱已经并入 `cost_yuan`）。
所以「tokens 与成本」在这部分不严格同口径——要严格比较请只看 `cost_yuan`。

### 2.2 问答侧（`output/qa/<kb_id>.jsonl`）

每次提问落盘 `timings`（`rewrite_ms` / `retrieve_ms` / `first_token_ms` / `total_ms`）与 `tokens`。
这正是 P3 §22 那个问题（首 token 3.3s 花在哪）的复现依据——**没有这组字段，只能点测、无法看分布**。

## 3. 统计页（新增「统计」tab）

后端 `app/services/stats.py` **只读聚合**，零写入、零迁移；前端 `GET /api/stats` 取数渲染。
没有新建数据库：数据本来就在磁盘上，且已经结构化，再抄一份只会产生"两边不一致听谁的"。

页面内容：

- KPI：已生成份数、生成花费、平均覆盖率、单份耗时 P50、提问次数、首 token P50、引用可信率
- 按课程一张表：完成/总数、花费、tokens、平均覆盖率、耗时中位、模型
- 问答一段：提问数、问答花费、首 token P50/P90、改写 P50、引用核验通过率
- 底部**如实标注**：哪些数字因为"旧记录没埋点"而显示 `—`，而不是 0

### 三条统计纪律（写在 `services/stats.py` 顶部，也有单测钉住）

1. **缺字段 ≠ 零**（见 §2.1）
2. **覆盖率 `-1` 表示"不适用/没算"，不能当 0%**——习题档、术语太少时本就不打分（沿用 P1 判据）
3. **估算成本与实测成本分开计**：服务商没回 usage 时是估算值，混进实测会让成本曲线失真

## 5. 横评怎么跑（脚本已就绪，未执行）

`scripts/p4_model_compare.py`，固定口径：同一批课件、`复习指南/详细`、**关视觉**、**关补漏**。

```bash
# 单家冒烟（用应用里已配的 key）
.venv/Scripts/python.exe scripts/p4_model_compare.py --providers deepseek --limit 2

# 四家横评（key 走环境变量；应用只存一份 key，横评要多份）
export P4_KEY_DEEPSEEK=... P4_KEY_ZHIPU=... P4_KEY_KIMI=... P4_KEY_QWEN=...
.venv/Scripts/python.exe scripts/p4_model_compare.py --providers deepseek,zhipu,kimi,qwen
```

已冒烟（2 份 Ceph 课件）：DeepSeek 覆盖率 **97%**（94% / 100%）、**¥0.065/份**、22.0s/份、无截断。

⚠️ **这个 ¥0.065 不能和简历里的"单节 ¥0.13"直接比**：横评关了视觉，那两份也基本无图。
比较模型必须同口径；换口径就要重跑，不能拿旧数拼新表。
