# P1 设计：覆盖率可见化

> 状态：设计稿（判据已用真实数据选定）
> 定位：**差异化主干**。M3 实测证明通用 agent 的遗漏是「静默且随篇幅递增」的
> （前半程 91.2% → 后半程 74.8%），用户不可能察觉；本功能把它测出来、摆出来。

## 1. 一句话

生成完成后，告诉用户：**这份总册覆盖了源课件的哪些内容、疑似漏了哪些**——
逐节给覆盖率，并把「疑似未覆盖」的条目连同出处页码列出来。

## 2. 判据（已实测选定，不是拍脑袋）

### 2.1 候选判据的实测（数据：M3 的 Ceph 课程 14 节 / 325 页）

| 判据 | 我方总册 | glm 文档 | 问题 |
|---|---|---|---|
| 整行字面匹配 | 29.6% | 6.8% | 太严，好文档也只有 29% → 不可展示 |
| 英文术语命中 | 97.5% | 90.2% | 语义对，但**只覆盖英文**，中文课无意义 |
| 行内 6-gram 复用率 | 61.6% | 24.7% | 区分大，但**语义是"有没有原样抄措辞"**，好文档仅 61% 且**看不出前后衰减** |
| **频次挖掘中文术语 + 英文术语** | **98.4%** | **83.0%** | ✅ 选定 |

选定判据的逐节明细（前 7 节 / 后 7 节）：

| | 前 7 节 | 后 7 节 | 全部 |
|---|---|---|---|
| 我方总册 | 98.2% | 98.5% | **98.4%** |
| glm5.3-flash | 91.2% | **74.8%** | 83.0% |

→ 好文档读数可信（98% 而非 61%），且**放大**了"通用 agent 后半程掉队"的特征。

### 2.2 术语从哪来（三条来源，全部零成本）

1. **英文/技术术语**：正则 `[A-Za-z][A-Za-z0-9_.-]{1,}`，长度 ≥2（`CRUSH` / `rados bench` / `pg_num`），
   并剔除**课件版式标签词**（见下）
2. **数字 + 单位/阈值**：`0.85` / `64KB` / `3 副本`。除「数字+单位」外也收**孤立小数**
   （阈值多为小数）；**不收孤立整数**——那会把页码序号当成知识点
3. **中文术语（频次挖掘）**：在**单份课件内部**出现 ≥3 次的纯中文 3–4 字串，且不含停用字
   （实测挖出的样例：分布式存储 / 单点故障 / 纠删码 / 横向扩展 / 结构化数据 / 存储池），
   再做**子串剪枝**（`文件系统` 保留，`文件系`/`件系统` 丢弃），避免同一知识点算三遍

**为什么用频次挖掘而不是分词**：不引入新依赖（jieba 词典 ~10MB），且"在一份课件里反复出现的
短中文串 ≈ 该课件的专有名词"这个假设对课件文本成立。实测候选数 7–64/份，量小、跑得快。

#### 版式标签词停用表（数据驱动，不是拍的）

把 M3 那门课 14 节的「我方总册缺失术语」**全量导出**后发现：缺的基本都是
`Key Points` / `Best Practices` / `Cause & Resolution` 这类**幻灯片装饰标签**、
页码/章节序号（`i` `ii` `iii`），以及示例主机名（`osd.0` `sda`）。
判据没错，是这些词**不该进术语表**——不放行会把好文档冤枉成 93%。

停用表实测效果（同一批数据）：

| 停用表 | 我方平均 | 我方最低 | glm 平均 | 我方前/后 | glm 前/后 |
|---|---|---|---|---|---|
| 无 | 95.8% | 89% | 88.1% | 97/94 | 95/81 |
| 保守标签词 | 97.0% | 91% | 89.0% | 98/96 | 95/83 |
| **选定（安全标签词+明确装饰词）** | **97.7%** | **95%** | **89.5%** | **98.6/96.9** | **95.1/83.9** |

**刻意不收** `node` / `monitoring` / `optimization` / `architecture` / `process` / `threshold`
这类**可能是真概念**的词——它们在某些课里就是知识点。
取舍依据：**宁可少报，不可冤枉**（频繁误报会让用户不再信任这个功能；少量漏报只是辅助参考的保守偏差）。

### 2.3 单条判定与聚合

- 术语命中 = 该术语（归一化去空白后）出现在成品文本中
- **节覆盖率 = 命中术语数 / 该节术语总数**
- **疑似未覆盖条目** = 未命中的术语，按来源页归位，输出「术语 + 页码」
- 同一术语跨页重复出现只算一次（否则重复页会稀释覆盖率）

## 2.4 适用范围：只对「复习指南 / 详细」打分

覆盖率**只在承诺「全面覆盖课件的知识点」的档位才有意义**，也就是「复习指南 / 详细」。
其它档位本就不追求全覆盖（习题生成只出题、重点总结只留要点、精简有字数上限）。

**实测证据（2026-09-14，把用户存量批次全跑一遍）**：

| 批次 | 档位 | 读数 |
|---|---|---|
| Ceph 课 14 节 | 复习指南 / 详细 | 95–100% ✅ 与人工核对一致 |
| 计算机网络 8 节 | 习题生成 / 重点总结 | **58–61%，被判「疑似遗漏较多」** ❌ |

后者是**用不成立的承诺去指责文档**。故：

- `applies_to(template, style)` 决定是否计算；不适用的档位 `coverage = None`（不显示徽标）。
- 但**不沉默**：`coverage_note` 说明原因，并告诉用户切到哪一档才能看。
- **前端二次门控**：档位不适用时不渲染徽标，即使某份带着历史/回填数据——
  不能只靠"生成时不算"。

> 这一条的设计原则和 §3 一致：**判据不能给出自己没有资格给出的结论。**

## 3. 如何避免误导用户（这一节和算法一样重要）

1. **用「疑似未覆盖」，不用「未覆盖」**：术语缺失也可能是被换了说法（如 `cipher suites`
   → 「加密套件」）。判据是词面，不是语义，必须如实说明。
2. **给依据，让用户 1 秒确认**：每条都带源课件页码，点开能对照原文。
3. **不作为错误、不阻断**：覆盖率低不报错、不自动重生成（重生成要花钱，决定权在用户）。
4. **不展示"绝对分"这种伪精确**：统一说「覆盖了源课件中 N/M 个知识点术语」。

## 4. 呈现

| 位置 | 呈现 |
|---|---|
| 批量 · 每份 | 该节覆盖率 + 疑似未覆盖条数（徽标色：≥95% 绿 / 85–95% 黄 / <85% 红） |
| 批量 · 总册页 | 整门课汇总一行 + 各节覆盖率列表 + 「疑似未覆盖」总清单（按节分组、带页码） |
| 单份 · 结果页 | 同一套（单份即 N=1 的退化情形） |
| 下载 | 总册正文**不改动**；覆盖率报告作为独立一节附在末尾（可选开关，默认附） |

**零模型调用**：纯文本比对，不花钱、可离线、可复现——这本身就是卖点。

## 5. 模块划分（分批实现）

| 批次 | 模块 | 内容 | 状态 |
|---|---|---|---|
| **B1** | `app/services/coverage.py` | 术语抽取（三来源）+ 节覆盖率 + 疑似未覆盖清单 + 汇总（纯函数，无 IO） | ✅ 0.8.5 |
| **B2** | 接进生成链路 | `run_single` 算覆盖率 → `GenerateOutcome` 携带；批量落盘 `batch.json`/`meta.json`/`coverage.json`；单份端点回传 | ✅ 0.8.6 |
| **B3** | API + 前端 | 批量/单份结果页展示徽标与清单；总册末尾附报告（**默认关**，可开关）；下钻端点 `GET /api/batch/{id}/coverage/{idx}` | ✅ 0.8.7 |
| **B4** | 文档与回归 | README 补覆盖率一节 + `scripts/verify_coverage.py`（体检 / 基准断言 / 外部文档对照） | ✅ 0.8.9 |
| — | `scripts/backfill_coverage.py` | 给存量批次零成本回填（用 job 目录里的 `extracted.json` + `doc.md` 本地重算） | ✅ 0.8.8 |

**B2 的实现要点**（细节见 CHANGELOG 0.8.6）：

- **单份端点改走 `run_single`**：原先进兼容壳只拿得到三元组，没有 usage 与 coverage。
  改后与批任务共用同一实现——单一实现，避免两套逻辑漂移。
- **算失败记 `None`，不抛错**：覆盖率是辅助信息，不能让它把已生成好的文档作废。
- **`coverage_percent` 默认 `-1`（无数据）而不是 `0`**：否则旧任务会被误读成「覆盖率为零」。
- **`reliable` 门槛**：术语数 < 8 时不给百分比（6 页样例只抽出 12 个术语，此时缺 1 个
  就掉到 92%，数字是噪声）。前端应显示「样本不足」。

**B1 独立性最强，先做它**——纯计算、可单测、不碰现有链路。

## 6. 验收标准（B1 已跑，实测结果附后）

1. **回归基准（真实数据）**——已跑：

   | 项 | 要求 | 实测 | |
   |---|---|---|---|
   | 我方总册（已知覆盖良好） | 平均 95–100%、**最低 ≥95%** | 平均 **97.7%**、最低 **95%** | ✅ |
   | `Ceph期末复习文档.md`（glm） | 明显更低，且**后段低于前段** | 平均 89.5%，前 95.1% / 后 **83.9%** | ✅ |
   | 判定文案 | 我方判「覆盖良好」、glm 后段判「建议核对」 | 完全吻合 | ✅ |

2. **速度**：单份（~25 页 / ~4000 字）实测 **平均 14ms、最慢 32ms**（要求 <1s） ✅
3. **零成本**：纯文本比对，无任何模型调用 ✅
4. **单测**：`tests/test_coverage.py` 15 个用例（三来源、标签词剔除、子串剪枝、
   纯英文课件、空源不误报、跨页去重、清单上限、阈值标定）全通过

**判定阈值**（按上述参照文档标定，不是拍的）：≥94「覆盖良好」/ 86–93「有少量疑似遗漏」/
<86「疑似遗漏较多，建议核对」——94、86 两个分界正好分开已知好文档（95–100）与
已知衰减文档（77–90），实测区间无重叠。

## 7. 明确不做（P1 v1）

- **不做语义/embedding 匹配**：要调模型或加重依赖；词面判据 + 「疑似」措辞已够用。
  若误报高到影响使用，再考虑「对疑似清单做一次轻量 LLM 复核」（P1.5，一次调用、几分钱）。
- **不自动重生成缺失部分**：花钱且需用户决定。
- **不修改总册正文**：报告是附加的，不是改写。
- **不做跨节术语去重/合并**：同一术语在多节出现属正常（各节独立复习）。
