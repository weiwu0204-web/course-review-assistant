# CV 融合方案：把视觉能力真正做进 ppt-reviewer

> 状态：设计稿（未改主链路）｜日期 2026-09-10
> 前提：**不是为了"有 CV 标签"而加 CV**，而是找"CV 真的能做、而多模态模型做不好"的环节。

## 一、先看数据（真实课件审计）

新增诊断工具 `scripts/image_audit.py`（只读，不依赖 numpy/opencv），对真实课件跑出的结果（19 页）：

| 页 | 尺寸 | 色数 | 边缘 | 横线 | 竖线 | 分类 |
|---|---|---|---|---|---|---|
| 3 | 555x401 | 1133 | 0.171 | 0.000 | 0.031 | 照片 |
| 5 | 640x720 | 1819 | 0.239 | 0.047 | 0.000 | 文字截图 |
| 8 | 968x283 | 662 | 0.149 | 0.148 | 0.000 | 文字截图 |
| 15 | 1160x497 | 164 | 0.040 | **0.922** | **1.000** | 表格/框图 |
| 16 | 670x258 | 888 | 0.156 | 0.000 | 0.000 | 文字截图 |
| 19 | 555x600 | 2672 | 0.098 | 0.000 | 0.000 | 文字截图 |

**结论：6 张图里 4 张是文字截图、1 张表格/框图、1 张照片。图片的主体是"文字/表格型截图"，不是照片。**

这正好落在两类方法的分水岭上：

| | 多模态大模型 | CV（OCR + 直线检测） |
|---|---|---|
| 强项 | "这是什么东西"（语义描述） | "逐字逐格精确还原"（结构） |
| 弱项 | 漏行漏列、数字抄错、公式符号丢 | 语义归纳（需要再交给 LLM） |

所以 CV 的介入点不是锦上添花，而是**在最容易出现"看着对、实际抄错"的地方接手**。

## 二、三个介入点（按 ROI 排序）

### P0 · 跨页图像去重（几乎零成本）

- **现状**：`extract_slide_images` 里 `seen` 是函数局部变量 → 只在本页内去重，跨页重复的示意图会重复计费。
- **方案**：把哈希集合提升到 `extract_pptx` 层；判重从 MD5 换成感知哈希（dHash）。
  - MD5 只能抓"字节完全相同"，重新压缩/裁剪过的同一张图抓不到；
  - dHash 抗缩放与轻微压缩，阈值 ≤5 判重。
- **收益**：直接省 token。当前样本无重复，但长课件（同一示意图在多章复用）很常见。
- **风险**：低。已有 `image_audit.py` 的 dHash 实现可直接复用。

### P1 · 文字/表格截图 → 结构化文本 ★ 最高价值

- **场景**：老师大量用"截图贴表格 / 公式 / 大段文字"。现在全部发给视觉模型，模型输出的是"描述"，会漏行漏列、把数字抄错。
- **方案**：
  1. 用分类器挑出"文字截图 / 表格框图"这两类；
  2. 走 CV 结构化管线：表格 → 直线检测 + 单元格切分 + OCR → markdown 表格；文字块 → 检测 + OCR → 纯文本；公式 → 检测 + LaTeX 识别；
  3. 结果作为**免费文本**并入提取结果，与现有的 OMML 公式、图表 XML 数据同级；
  4. 只有结构化失败的图，才回退给视觉模型。
- **技术选型（都不需要自己训练）**：
  - **RapidOCR**（ONNX，中文友好、轻量、可离线）—— 首选
  - PaddleOCR PP-Structure（表格识别更完整，但依赖重）
  - pix2tex / LaTeX-OCR（公式）
- **收益**：准确率↑ 且 成本↓（离线零 token）。**这是简历上真正能写"CV 工程"的部分。**

### P2 · 装饰图语义分级（降本）

- **现状**：只有两道物理过滤——`MIN_IMAGE_PIXELS = 150*150`、`FLAT_STDDEV = 30`。
- **漏掉的**：有纹理的渐变背景、边框、装饰纹样、大尺寸 logo。
- **方案**：用审计脚本里的低层特征（唯一色数、边缘密度、长直线占比、行间隙率）做规则分级；样本足够后再考虑轻量分类器。
- **前置条件**：先跑 20–30 份真实课件收集数据、校准阈值（先量再改）。
- **优先级低于 P1**：当前样本显示误判不多。

## 三、明确不做的事

- **不做"整页渲染 + 通用图像理解"**。PPT 里的文本、表格、公式、图表数据本来就能免费解析出来，渲染成图再让模型看一遍是**倒退**（更贵、更不准）。只有扫描版幻灯片才需要渲染。
- **不自己训练检测/分割模型**。RapidOCR 这类现成工具已够用，训练投入产出比不成立。
- **不为 CV 而 CV**。判断标准永远是：**CV 能不能比现有方法更准、或更省？** 两个都不能就说明不该做。

## 四、与遥感科研的连接（关于"研究方向帮助不大"）

**任务层面确实不相关，方法论层面高度同源。**

| 遥感道路提取 | 文档结构提取 |
|---|---|
| 从卫星图提取线状拓扑 | 从版面提取表格线 / 文本块结构 |
| 边缘检测、形态学、连通域分析 | 直线检测、形态学、连通域分析 |
| 类别不平衡（道路像素占比小） | 目标区域占比小 |
| 精度评估（IoU / Dice / F1） | 结构还原准确率 |
| 数据集构建与标注 | 样本标注与阈值校准 |

**共同母题：从非结构化图像中可靠地提取结构化信息。**

所以正确的做法不是让 ppt-reviewer 去"蹭"遥感，而是：

1. **科研往"遥感 + 多模态大模型"靠**——遥感视觉-语言模型（RS-VLM：图像描述、视觉问答、图文检索）是当前真实热点，**且能发论文**，比纯道路提取更容易做出新意。
2. **不改变现有方向的前提下焊入多模态**：在论文里加多模态大模型的对比实验（如用 SAM / CLIP 做道路提取的零样本基线）。
3. **求职叙事**："我关心的共同问题是怎么把图像里的结构可靠地提取出来——不管是路网还是表格。"

这样科研与求职收敛到同一条主线：**多模态视觉理解**。毕业优先，不为求职改论文方向。

## 六、0.8.0 实测补充：OCR 的优先级上升了

PDF 支持落地时的实测（详见 [PDF-SUPPORT.md](./PDF-SUPPORT.md)）给这份方案加了新证据：

- 5 份 PDF 课件里 **4 份文字层是损坏的**（「打印成 PDF」导致 ToUnicode 映射表丢失），
  字形能正常显示但中文字符读不出来——**对程序而言等同于图片型**。
- 这推翻了原判断「多数课程课件有文字层，OCR 不划算」：
  **「有文字层」不等于「能提取出文字」**。
- 但结论不是「改用纯 OCR」，而是**整页渲染 + 视觉模型**：PDF 自带渲染器
  （pypdfium2 / PyMuPDF），比 PPT 侧的整页渲染（需 PowerPoint COM）更容易落地，
  渲染出来还能让模型理解版面。
- 因此 **P1 的范围应扩展**为「PPT 里的表格/文字截图 **+ 损坏或扫描版 PDF 的整页**」——
  两者的共同解法都是「渲染成图 → 结构化理解」，可以一次投入两处受益。
