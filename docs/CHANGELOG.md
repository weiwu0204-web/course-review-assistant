### 一个稳定的行为特征（值得记）

三次实验的轮次结构完全一致：**2 轮侦察（看清单、读源页）+ 第 3 轮提交补丁**。
这既印证了"停滞检测不能把侦察轮算成停滞"那处修复是对的，
也说明**这个 Agent 的行为是可预期的**（不是碰运气）。

### 诚实记录的两条

- **零触发针对的是"覆盖率已达标的节"**：`398cceda` 有两节真实覆盖率 89%，
  判定为**应当触发** —— 这是正确行为，不是误触发。开启自动补漏时它们会真被补（实测 89%→100%）。
- **档位不适用时即使覆盖率低到 58% 也不触发**（`d64a9102` 习题生成档）——
  守住了"不拿不成立的承诺指责文档"这条线。

## [0.8.11] - 2026-09-15（P2 覆盖率闭环 · P2b Agent 循环）

主题：**补齐 verify → repair 的另一半——让 Agent 自己去补漏**。
设计见 [P2-REPAIR.md](./P2-REPAIR.md)（含真实冒烟与踩坑记录）。

### 新增

- **`app/services/agent_repair.py`** —— Agent 循环 + 三个 guardrail：
  - **轮次**（上限 5）、**成本**（生成花费的 40%，无基线时用绝对上限）、**停滞**（提醒一次再停）
  - **回滚**：补完重检，覆盖率没提升就交还原文档（`rolled_back=True`）——用户永远不会拿到
    "被改乱了却没变好"的文档
  - 两条路径：`autonomous`（模型自主调工具）/ `orchestrated`（provider 不支持 Function Calling
    时的降级，工具照用但顺序由程序定，**如实记录 mode 不冒充自主 Agent**）
  - 失败绝不作废文档（与 P1 覆盖率回检同一原则）
- **`GenerateRequest.enable_repair`（默认关）** + `run_single(repair_workdir=...)`：
  只有「复习指南 / 详细」且覆盖率 <94% 且样本可靠才触发——**对生成良好的文档零触发零成本**。
- **批量侧**：逐 job 记 `repair_summary`、补漏花费计入该份成本（批次总花费是各 job 求和，
  自动带上）、`meta.json` 落完整 repair 记录、补漏过程文件放在该 job 的 `repair/` 下。
- **前端**：单份与批量各加「覆盖率不足时自动补漏」勾选框；覆盖率徽标旁显示
  「已自动补漏 N 轮：X% → Y%，¥Z」——**用户有权知道文档被补过**。
- **`scripts/smoke_repair.py`** —— 真实冒烟脚本：拿真实课件人为删掉部分小节制造低覆盖，
  再让真模型去补，验证「MCP 子进程 + 真实 Function Calling」能协同。

### 真实冒烟（可控实验）

真实课件（19 页）+ 删掉 30% 小节 → **58% → 100%**（该文档原版自身只有 67%），
3 轮（侦察 → 读 8 页 → 提交 4 个补丁），**总成本 ¥0.059**，
补入内容带来源页码且是实质知识而非术语罗列。

### 修复：三个只有"真跑"才能发现的问题

1. ★ **停滞检测把纯侦察轮也算成停滞** —— 真实模型的节奏是「先看清单 → 再读源页 → 最后提交」，
   前两轮覆盖率必然不动，结果被判定空转、**一行都没补上就退出**（首轮冒烟 58%→58%、补丁 0 个）。
   改为：只有**这一轮调用过 `submit_patch`** 才参与停滞判定。
   （单测发现不了——假 LLM 的剧本是测试自己写的，会直接提交；**故补了回归测试**）
2. **轮次上限 3 不够**：真实节奏需要"1 轮侦察 + N 轮读页 + M 轮提交" → 提到 5。
3. **`final_document()` 在零补丁时抛 `FileNotFoundError`**：server 只在成功应用补丁后才写盘，
   于是"模型判断不需要补"这个**正常结果**被当成 error → 改为退回会话开始时的文档。

另修：批量 worker 是否传 `repair_workdir` 改为**按函数签名判断**（原先按"是否传了 generate_fn"判断，
但测试是 monkeypatch 掉 `br.run_single` 的，会把 3 参数假函数当支持新参数的真实现 → 整批变 `partial`）。

### 测试

`tests/test_agent_repair.py` **11 个用例**（假 LLM + 真 MCP 子进程）；
前端渲染检查 20 项；全量 **164 passed + 1 skipped**。

## [0.8.10] - 2026-09-15（P2 覆盖率闭环 · P2a MCP 工具层）

主题：**把覆盖率回检从「给人看的报告」升级为「给 Agent 用的反馈信号」**——
生成 → 回检 → 缺失 → Agent 调工具定向补漏 → 再回检。设计见 [P2-REPAIR.md](./P2-REPAIR.md)。

本批只做**工具层**（尚未接模型，**零成本**）：

- **`app/mcp_server.py`** —— MCP Server（stdio），4 个工具：
  `check_coverage`（覆盖率 + 缺失清单 + **文档大纲**）/ `list_missing` / `read_source_page` /
  `submit_patch`。**每节一个会话**（独立子进程，用环境变量注入上下文），
  模型只能通过这 4 个工具观察与修改一个内存副本，**拿不到文件系统、拿不到原始课件**（最小权限）。
- **`app/services/mcp_client.py`** —— 宿主侧封装：起子进程、调工具、取最终文档。
- **`app/services/doc_patch.py`** —— 补丁插入纯函数。**「只补缺失、不改写原文」由程序结构保证**：
  模型只提交「插到哪个标题后 + 补什么」，不输出修订全文——提示词约束会被违反，程序插入不会。
  定位失败不报错（落文末兜底小节），避免模型反复重试白烧 token。

### 修复 / 工程

- **uv 安装 pywin32 不完整 → mcp 无法 import**：wheel 里 611 个文件只装进去 347 个
  （缺整个 `win32com/`、`win32comext/`，以及 `win32/_win32sysloader.pyd` 等 12 个 `.pyd`）。
  根因是 **uv 不执行 wheel 的 post-install 步骤**。新增 **`scripts/fix_pywin32.py`**
  幂等补齐（只动当前 venv，不写系统目录、不需管理员），可拷到其他 uv 项目复用。
- 新增 **`scripts/mcp_probe.py`** —— Windows + Git Bash 下的最小 MCP stdio 探针
  （列工具 / 调用取结果 / 中文参数往返）。**先验证协议层再写模块**，避免闷头写完才发现不通。
- `requirements.txt` 增加 `mcp>=1.30,<2`（锁 <2：2.x 额外拉 httpx2 / opentelemetry，1.30 已够用）。

### 测试

`tests/test_mcp_server.py` **12 个用例**，分三层：
纯函数（插入/定位/CRLF/边界）→ 会话逻辑（校验、回检、落盘、重复提交拦截）→
**真起 MCP 子进程走 JSON-RPC 的端到端**。
全量 **153 passed + 1 skipped**（P2a 前为 141）。

## [0.8.8] - 2026-09-14（覆盖率按档位门控 + 存量批次回填）

主题：**先堵住一个会让功能说假话的口子，再让老数据也能看到效果。**

### 修复：覆盖率只对「复习指南 / 详细」有意义——其它档位不再打分

回填脚本一空跑就暴露了：用户四批里**三批的数字是错的**。

| 批次 | 档位 | 原始读数 |
|---|---|---|
| Ceph 课（14 节） | 复习指南 / 详细 | 95–100% ✅ 与人工核对一致 |
| 计算机网络 | 习题生成 / 详细 | **58–61%，被判「疑似遗漏较多」** ❌ |
| 计算机网络 | 重点总结 / 详细 | 同样偏低 ❌ |

**这些档位本就不追求完整覆盖**（习题生成只出题、重点总结只留要点、精简有字数上限），
硬打分等于**用一个不成立的承诺去指责文档**，会给出吓人且错误的结论。故新增
`coverage.COVERAGE_TEMPLATES = {("复习指南", "详细")}` 与 `applies_to()`：

- 不适用的档位**不计覆盖率**（`coverage = None`），也就不显示徽标；
- 但**不沉默**：`coverage_note` 说明原因并告诉用户切到哪一档才能看
  （"沉默会让用户以为功能坏了"）。
- **前端二次门控**：即使某份带着历史/回填数据，只要档位不适用也不渲染徽标——
  不能只靠"生成时不算"来保证，存量数据可能已经有值了。

### 新增 `scripts/backfill_coverage.py`

给存量批次回填覆盖率（本功能上线前跑的批次 `coverage_percent = -1`，界面不显示徽标；
重跑要花钱，而**课件与生成文档都还在 job 目录里**，纯本地重算零成本）。

- 数据来源：`job目录/extracted.json`（**当时实际用的那份**，与当时结果一致）→
  兜底才现场提取源课件；正文取 `doc.md`。不调模型。
- 安全：默认 `--dry-run` 只报告；写入前把 `batch.json` 备份为 `.bak-<时间戳>`；
  已有覆盖率的跳过（`--force` 可重算）；**档位不适用的批次整体跳过**。
- 实测：18 份已计算（复习指南档），2 个批次因档位不适用整体跳过；汇总数字如实区分三者。

### 测试

新增档位门控用例（含空值按默认档理解、说明文案必须指出"切到哪一档"）。
全量 **141 passed + 1 skipped** + 16 项 JS 渲染检查。

### 已知边界

- 停用词表**刻意保留**了 `monitoring` / `architecture` / `mechanism` 这类"可能是真概念"的词，
  在本课程里它们其实是幻灯片版式标签，会出现在「疑似未覆盖」清单里（每节约 1–4 条）。
  取舍是**宁可少报不可冤枉**：换一门课这些词可能就是知识点。实测不影响判定
  （每节仍判「覆盖良好」）。
- 存量 `batch.json` 里可能残留 `coverage_percent: null`（旧版 `from_dict` 写入的）。
  读取时会规范成 `-1`，功能无影响；不想留痕可用 `--force` 重跑回填覆盖该批。

## [0.8.7] - 2026-09-14（P1 覆盖率可见化 · B3 前端展示）

主题：**把覆盖率摆到用户眼前**。B1 算出来、B2 传到链路，B3 让它可见、可下钻。

### 新增

- **单份结果页**：生成完成后在标题下方显示覆盖率徽标（≥94 绿 / 86–93 黄 / <86 红，
  与后端 `verdict()` 阈值一致），点「疑似未覆盖 N 项」展开清单，每条带**源课件页码**。
- **批量任务列表**：每节显示同款徽标；点开才按需请求
  `GET /api/batch/{batch_id}/coverage/{idx}` 取明细（`batch.json` 只存摘要，
  避免轮询时反复读盘）。总册视图里这块自动隐藏。
- **「附覆盖率自查」开关**（单份 + 批量各一个），**默认关**（用户选择）：
  总册/文档是拿来复习与分享的，塞一段自查报告会让同学以为这份不完整。
  勾选后报告附在**文档末尾**（表格 + 平均覆盖率 + 逐条明细带页码），
  **不改动正文**。批量走 `rebuild_master()`，单份只附加在返回的 markdown 上。
- `MIN_TERMS_FOR_PERCENT = 8`：术语太少时不给百分比，显示「覆盖样本不足」——
  6 页样例只抽出 12 个术语，此时缺 1 个就掉到 92%，数字是噪声。

### 修复：一个潜伏已久的字段反序列化 bug（本次被新字段暴露）

`JobRecord.from_dict()` 原为 `{k: data.get(k) for k in __dataclass_fields__}`，
**`data.get` 对缺失键返回 None，把 dataclass 默认值覆盖掉了**。后果：

- 旧 `batch.json`（没有 `coverage_percent` 字段）加载后该值为 `None`；
- 前端 JS 里 **`null >= 0` 恰好为 true** → 会渲染成「覆盖 null%」；
- 后端 `None >= 0` 在 Python 里**直接抛 TypeError** → 在旧批上点「重试」会崩
  （`rebuild_master()` 里就有这行比较）。

这是**所有「后来新增的字段」共有的坑**，不只是覆盖率。改为只取
`data` 中**存在且非 None** 的已知字段，其余落回默认值；
另在前端把守卫改成显式 `!= null`，并在 `rebuild_master` 加一层 `or -1` 兜底。

> 这个 bug 是**查真实接口返回**才发现的：字段在响应里存在，但值是 `null` 而不是 `-1`。
> 只跑单测不会暴露它——单测里的批对象是新建的，字段有默认值。

### 测试

- 新增 `tests/test_coverage_ui.js`：用最小 DOM 桩把 **index.html 里真实的渲染代码**
  抽出来执行（不复制粘贴，避免两处漂移），16 项断言覆盖配色阈值、样本不足、
  无数据隐藏、点击展开、明细含页码与「疑似」措辞、null 守卫。
- `test_batch_runner.py` 补 2 个：缺失/null 字段落回默认值；加载「旧格式」
  `batch.json` 后重建总册不得崩。
- 全量 **137 passed + 1 skipped**（pytest）+ **16 项 JS 渲染检查全通过**。

### 已知边界

- **存量批任务不会显示徽标**：它们是本功能之前生成的，`coverage_percent = -1`（未计算）。
  要看效果需新跑一次生成。
- 覆盖率明细依赖 `coverage.json`；缺失时前端显示「这一节没有覆盖率明细」而不是 0%。

### 下一步（B4，未做）

文档与回归：README、用 M3 数据当回归基准固化成可重复的验收脚本。

## [0.8.6] - 2026-09-14（P1 覆盖率可见化 · B2 接入生成链路）

主题：**B1 算出来的覆盖率，接到用户能看到的地方**。

### 接入

### 修复：Windows 上 `batch.json` 并发读写偶发 `PermissionError`（轮询会偶发 500）

`persist_batch` 是「写 .tmp 再 replace」的原子写，但有两个 Windows 现实问题：
① 并发写共用同一个 `.tmp` 文件名会互相踩；② **`replace` 换名的那一瞬间目标文件处于
换名窗口，此时并发的读会拿到 `ERROR_SHARING_VIOLATION`（Python 表现为 `PermissionError`）**。
而"worker 每完成一份写一次 + 前端每 2 秒轮询读一次"意味着**撞车是常态**。

修复：tmp 名带进程/线程标识 + 写侧短退避重试；**读侧同样要重试**——
实测只给写侧重试不够（`GET /api/batch/{id}` 轮询会偶发 500）。
读侧重试抽成 `read_text_retry()`，`load_batch()` 与 `batch_list()` 都走它。
补 2 个回归测试；全量测试连跑 5 次无偶发。

> 教训：**"只剩一侧"的并发修复不算修复。** 第一版我只改了写侧，测试仍然偶发失败，
> 拿到完整堆栈（失败在 `GET` 轮询的读路径上）才定位准确。

## [0.8.1] - 2026-09-11（用户实测反馈修复）

主题：**用户首次真实跑批量生成，暴露两个问题**——一个是阻断性 bug，一个是
输出上限设得过低。两条都属「测试全绿但真机不灵」，值得记下它们为什么漏网。

- **修复（阻断性）：建批后进度永远停在 0/N，点「停止」才刷出结果。**
  根因是接口契约不一致：`POST /api/batch/start` 返回的是 `batch.summary()`
  （**没有 `jobs` 字段**），而前端 `enterBatchRun()` 的调用顺序是
  `renderBatchStatus(detail)` → `startBatchPolling()`——首屏渲染在
  `d.jobs.forEach` 处抛 TypeError，异常被 `doStartBatch` 的 try/catch 吞掉，

  - 漏网原因：既有测试只断言 `_wait()` 的轮询结果，**从未检查过建批响应本身的
    字段形状**。已补断言：建批响应必须含 `jobs` 且状态为 waiting。

主题：**支持上传 PDF 课件**。老师发的课件与 GitHub 上的公开课件越来越多是 PDF。

- `app/services/pdf_extractor.py`（新增）：pypdf 提取 PDF 文本，产出结构与

    17.9%–42.1%，而健康的中文 PDF（简历）与英文 PDF（LLM 课件）都是 **0.0%**，

  提示走 OCR。
- 修复：**进程重启后批任务假死**。批任务跑在后台线程里、线程登记在内存

- predict 实测结论（课件.pptx + 通用题库 predict 端到端，人工核对）：
  - 仿题型结构成立：单选 4 / 多选 2 / 判断 2 / 简答 2，贴近题源题型比例；
  - 首版出现照抄题源原题（三次握手题几乎原样搬入，且该考点 PPT 未讲）→ 规则补漏；
  - 防照抄规则生效后：全部重拟，场景化改编（微信消息、机房广播风暴）、换问法换干扰项

## [0.5.0] - 2026-09-02

主题：**题目成为一等公民——真实题源（往年试题）进复习文档。**

产品决策（来自 Step 0 质量判决的用户反馈）：
- 雾围明确：纯 PPT 内容总结不够，复习文档必须配**真实的题目**练手；
- 「自己出的思考题完全没必要」——每所大学期末卷有自己的风格，开放式思考题不是考试形态。
  因此砍掉「深度思考题」类自拟内容（复习指南模板禁止输出开放讨论题）；
- 题目来源优先级：**上传本校往年试题（直搬/参考） > 网上搜题（见下） > 模型兜底出模拟题**。
- 搜题可行性实测（WebSearch）：网上只有**通用题库**（如 CSDN 计网题库）与英文刷题站，
  **搜不到具体某校真题**。通用题可练基础概念，但学不到本校风格 → 上传本校题不可替代。
  结论：桌面软件内置联网搜题不现实（无稳定搜索通道），「帮你搜」留给 agent 场景。

### 新增

- `POST /api/exam` —— 往年试题解析上传：支持粘贴文本或上传 `.txt/.md/.pdf`
  （pypdf 解析，UTF-8/GBK 双解码；扫描版 PDF 无文本层时友好报错），
  返回 `exam_id`，试题存 `uploads/exams/<id>.txt`
- `GenerateRequest` 扩展 `exam_id` / `exam_mode`：`direct`=原样搬运成「历年真题」章节；
  `predict`=分析原卷题型结构/难度/风格后仿出「预测题」（明示非原题）
- `ai_generator.py`：新增题源段落（最高优先级，`EXAM_MAX_CHARS=20000` 截断保护输入）；
  复习指南/重点总结模板**禁止**输出「深度思考题/开放讨论」；习题生成模板在无真实题源时
  只出「模拟练习题」且不得冒充任何学校/年份的真题；要求不得编造 PPT 外数据
- `app/static/index.html`：新增「往年试题（可选）」区块——粘贴框 / 上传文件 / 解析按钮 /
  试题用法选择；解析后显示字数与预览；生成请求自动携带题源
- 依赖：`pypdf>=4`
- `tests/test_exam_prompt.py` —— 5 个纯函数测试：无题源不带题、直搬原样保留、参考预测非原题、
  非法模式回退直搬、超长题源截断

### 变更

  上传课件 → 文本试题解析 → 扫描版 PDF 报错 → 直搬真题生成 → 产物落 `eval/`

## [0.3.0] - 2026-09-01

主题：**给「分层提取」做一次消融评测，验证每一层的边际贡献。**

### 新增

- `scripts/evaluate_generation.py` —— 三配置消融评测（只提取文本框 / 分层无图 / 分层+视觉模型），
  以样例课件为 ground truth（`make_sample.py` 源码推导，无需人工标注），量化五类指标：
  知识点召回率、硬数据保留率、备注考点、图片独有内容、幻觉率（参考）
- `eval/generation_eval_results.json` —— 评测结果（含逐配置生成全文与指标明细）

### 实测结论（样例 6 页）

| 指标 | 只提取文本框 | 分层无图 | 分层+视觉 |
|------|:---:|:---:|:---:|
| 知识点召回率（9 项） | 100% | 100% | 100% |
| 硬数据保留率（11 项） | 18% | 73% | 73% |
| 备注考点（4 项） | 50% | 100% | 100% |
| 图片独有内容（3 项） | 33% | 33% | 100% |
| 幻觉率（参考） | 6% | 15% | 8% |

- 分层提取的最大价值在**硬数据**（表格/图表数值 18% → 73%），核心概念本身在文字层已全量召回
- **教师备注**是投入产出比最高的一层（50% → 100%），「白捡的重点」得到验证
- 视觉模型的边际贡献仅在**图片独有内容**（33% → 100%）；若图片是重复信息，开视觉不提升质量
- 幻觉率维持低位，可疑行多为结构词（如「核心概念」），无硬性编造

### 已知限制

- 图表分类轴（n=100 / n=1000 / n=10000）三种配置均未完整转写——数据已提取但模型生成时省略，
  后续在提示词中显式强调图表数据

## [0.2.0] - 2026-08-30

主题：**把免费的那一层用满，再谈多模态。**

### 新增

**提取能力**
- 备注页提取 —— 老师常把考点写在这里，零成本，投入产出比最高的一处
- OMML 公式解析 —— PowerPoint 2007+ 的公式是 XML 不是图片，直接读
- 图表数据提取 —— 从 `chart.plots` 读分类/系列/数值，比让模型「看」更准
- 嵌入图片导出 —— 统一转 PNG，跳过无法渲染的 WMF/EMF

**多模态**
- 有图片时自动切 `deepseek-v4-flash-vision-exp`，无图时退回纯文本模型
- 提示词里标注图片所在页码，并明确要求「不要凭空编造图片中不存在的结论」
- 单请求 600 张 / 32MiB 上限保护，超出丢弃而不是让请求失败

**图片过滤（三层）**
- 面积 < 150×150 丢弃
- 灰阶标准差 < 30 丢弃
- 同一张图出现 ≥3 页丢弃

**工具**
- `scripts/diagnose.py` —— 逐页诊断提取覆盖率，估算视觉模型成本
- `scripts/preview_images.py` —— 把图片拼成联系表，肉眼判断哪些值得发
- `scripts/make_sample.py` —— 生成模拟真实课程的样例 PPT
- `conftest.py` —— 让 `uv run pytest` 能找到 app 包

### 修改

- `max_tokens` 从硬编码 4096 改为可配置，默认 8192（原值会让长文档被截断）
- 默认模型从 `gpt-4o-mini` 改为 `deepseek-v4-flash`
- 每次上传独立 uuid 目录，修掉同名文件互相覆盖
- 前端：加视觉开关，显示图片数与备注字数，只接受 .pptx
- `collect_images()` 返回三元组，被过滤的数量打印到终端

### 修复

- **`.ppt` 友好拒绝** —— 原来会走到 python-pptx 抛异常，
  现在在入口就拦下并提示「另存为 .pptx」
- **`deepseek-chat` → `deepseek-v4-flash`** —— 前者已于 2026-07-24 永久停用
- **`Image.stat()` 不存在** —— Pillow 12.3 上没有这个快捷方法，
  改用 `ImageStat.Stat(im)`；当时这个 bug 导致所有图片被误判为纯色、
  提取数直接归零
