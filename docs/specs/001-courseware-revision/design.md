# 001 服务基础设计

- 数据：账号与有时效的会话；课程归属账号；课件归属课程，当前版本用递增版本号；版本行记录对象键。课件和试题用同一版本机制，按材料类型区分。
- 发布：上传到新的私有对象键，确认保存后按基准版本更新课件和新增版本行；冲突时保留数据库里已发布的版本。失败时未发布对象可以清理，引用存在的对象继续保留。
- 批次：提交时在数据库事务内确认归属、固定有序输入和可选试题版本，写入批次和逐份任务。幂等键由账号限定，保存参数摘要用于识别冲突。
- 执行：job 从 queued 领取为 running，使用领取标记和数据库时间的租约。过期后可以重新领取；当前标记才可提交和续租。结果写入每次尝试独立的对象键。重试可能再次调用模型；只有持有效领取标记的一次结果对外可见。最后从可见的节次产物按顺序汇编。
- 测试：先验 v1/v2、归属、上传失败、幂等；再验真实数据库双 worker 竞争、租约过期和进程重启。共享数据库和对象桶必须是专为本次验证创建的实例或命名空间。
- 回滚：保留桌面标签和独立目录；服务在候选版本出错时停掉候选 API/worker，换回最近通过的提交或镜像，保留数据库与对象数据。当前只增加服务专用表。生产迁移先验证旧版本可读；不自动执行会删除用户数据的降级迁移。
