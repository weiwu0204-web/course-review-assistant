# 002 技术方案

- 复用提取、BM25、引用核验及流式生成。版本清单和库的所属人写入数据库，文本分块写入私有对象。服务端生成唯一显示名处理同名课件；源版本清单仍可核对。建库受文件大小、页数和文本上限限制。库规模和调用频率超过私有预览范围前，再把建库接到任务队列。
- 问答状态和历史按 owner 与库关联。流程为加载已授权知识库 → 检索 → 流式生成 → 核验 → 记录历史。默认演示使用来源文本，不访问供应商；真实模式从服务环境取模型设置。未命中提供可解释结果；已经开始流式返回时用通用错误事件，避免暴露供应商细节。
- 002 新增知识库、问答记录、章节生成诊断和迁移登记表。原 schema_revisions 的兼容版本仍为 1，旧镜像的就绪检查因此能继续通过。002 只增加表；降级时停候选写入并保留所有数据，旧镜像仍可处理原来的批任务。用独立测试库演练迁移与重启。
- 批任务未启用补漏时，幂等摘要沿用 001 的计算方式。降级前先停新写入并等正在运行的任务结束；要求补漏的待处理任务等 002 恢复后再执行，001 不具备补漏诊断。
- 服务页用静态 HTML/CSS/JS 和 /api/v1；一份样式，一个 API 客户端，生成与问答独立。把沉淀文档按运行手册与历史设计分开；第一批目录调整保留旧接口和文档链接。
